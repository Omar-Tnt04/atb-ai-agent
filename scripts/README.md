# Scripts

This folder contains helper scripts for the generic website AI agent.

The goal of these scripts is to help the agent work on a target website by generating the context and navigation data needed for ASK mode and ACT mode.

## Main scripts

### `build-site-context.js`

Builds the website context used by **ASK mode**.

It collects structured public-site information and produces context data that helps the assistant answer questions about the target website, its pages, services, contact information, documents, and public content.

Rendered crawl output (not read directly by ASK mode):

```text
site-context/<domain>/context.json
```

Convert the validated crawl into the backend runtime schemas:

```powershell
node scripts/build-ask-context.js site-context/atb.tn/context.json site-context/atb.tn
```

This creates `ask-context.json` and `ask-exact-context.json` from the same fresh
rendered evidence. It preserves source URLs and capture timestamps, splits long
pages into retrieval chunks, and refuses empty crawls or unresolved failed URLs.
Stage and review crawl output before replacing runtime files. Restart the backend
after replacing context so its in-memory retrieval caches use the new content.

---

### `build-site-index.js`

Builds the website index used by **ACT mode**.

It crawls/discovers pages, links, documents, forms, and navigation targets so the agent can open the right page or document when the user asks it to act.

Main output:

```text
site-context/<domain>/site-index.json
```

This file is used by the backend semantic navigation pipeline.

To generate ASK and ACT from one validated capture (recommended for refreshes):

```powershell
node scripts/build-site-context.js --url https://atb.tn --out site-context/atb.tn/context.json --max-pages 1000 --max-depth 10 --ollama off
node scripts/validate-site-context.js site-context/atb.tn/context.json
node scripts/build-ask-context.js site-context/atb.tn/context.json site-context/atb.tn
node scripts/build-site-index.js https://atb.tn --context site-context/atb.tn/context.json
node scripts/validate-site-index.js site-context/atb.tn/site-index.json
```

For interrupted captures with saved output or transient failures, repeat the first
command with `--resume site-context/atb.tn/context.json --timeout 60000`.
Resume retries failed/weak pages and discovers remaining links. Known HTTP 404/410
links stay recorded as exclusions; other failures block runtime conversion.
When a site outage prevents completing a reviewed capture, `--allow-partial` on
both conversion commands publishes only captured evidence while preserving
`meta.status: "partial"` and every failed URL. It never fills gaps with old content.
The crawl skips technical CAPTCHA endpoints and media downloads, retains CSS and
scripts, and waits for the full HTML response before extracting rendered evidence.

---

### `export-playwright-capture.js`

Exports rendered website evidence using Playwright.

This script captures public pages in a real browser-like environment. It can collect rendered page text and screenshots so the context-building workflow can be reviewed, audited, or improved.

This is useful for:

```text
- verifying what the website actually displays
- building better ASK context
- auditing generated context
- collecting supervisor/demo evidence
```

Generated captures should not be committed to GitHub.

---

### `run-widget-task.js`

Runs widget/agent tasks from the command line.

This is useful for testing the agent behavior without manually using the browser every time.

---

### `start-dev.ps1`

Starts the local development environment on Windows.

This is useful for launching the backend, widget, and related local services during development or demos.

---

## Supporting scripts

Other scripts in this folder are supporting utilities for development, validation, cleanup, testing, benchmarking, or internal workflow automation.

They are not the main scripts a reviewer needs to understand first.

The main architecture depends on:

```text
1. build-site-context.js
2. build-site-index.js
3. export-playwright-capture.js
4. the generated ask-context.json and site-index.json files
5. the backend semantic ASK/ACT services
6. the widget frontend
7. the browser demo bridge
```

## Runtime files generated by scripts

The important generated runtime files are:

```text
site-context/<domain>/ask-context.json
site-context/<domain>/site-index.json
```

For the current demo target, these files are committed so the agent can work after cloning the repository.

Generated screenshots, Playwright captures, semantic caches, logs, and temporary files should not be committed.
